# B12 — Slurm por celda y recuperación

Manifiesto `campaign.json` verificado antes de distribuir trabajo. Selección por ID o índice canónico; índice inválido se rechaza antes de crear la celda. Cada batch train/resume procesa una sola celda. Los archivos 06–13 cubren preflight, freeze, smoke con recuperación, train, evaluate, resume, report y dry-run. Todos solicitan CPU, llevan el comentario requerido y no instalan dependencias.

Bloqueo `flock` por celda A1; el segundo writer falla. Una completa se valida y reutiliza. Parcial restaura collector, agente exacto, Q anterior, replay, RNG y entorno desde el checkpoint confirmado. Señales USR1/TERM/INT solo activan un flag; se publica al llegar a frontera segura. Los batches train/resume declaran 3.480 segundos por intento para una solicitud de una hora (ajustar el argumento si cambia `--time`). Antes de un fit se compara el mínimo entre ese tiempo restante y el presupuesto acumulado con mayor costo de fit observado y margen declarado. Esto no garantiza una cota para el siguiente fit. SIGKILL puede repetir hasta el intervalo de checkpoint; no se promete recuperar transiciones posteriores al último commit.

Evaluación independiente greedy: referencia inmutable del checkpoint, campaña, grupo/semillas/horizonte/política/runtime. Cada episodio es una unidad A1 recuperable con presupuesto propio. Repetir uno completo no repite el episodio. Presupuestos concurrentes son por unidad y se suman en reportes, sin compartir un contador mutable. Las extensiones requieren ID, segundos y motivo; no reinician consumo. Intentos registran nodo, recursos, entorno, versiones, duración y reanudación. Una muerte no controlada puede dejar un intento sin duración final, que debe tratarse como desconocida.

La corrección del 14/10/2026 conserva cada intento sin cierre como `record_status=incomplete`: fin, duración y RSS desconocidos se exportan como `null`, incluidos registros antiguos que omitían esas claves. No se reescribe el intento muerto al reanudar ni se infiere el instante de muerte desde el inicio siguiente. Si falta la memoria de algún intento, el máximo global queda desconocido; `peak_rss_bytes_known_max` conserva el máximo medido de los demás. El tiempo acumulado en `budget.json` sigue intacto y se etiqueta como límite inferior registrado cuando una muerte abrupta pudo dejar consumo sin guardar. `measurements` no utiliza ese límite como una tasa de costo completa. Se mantienen los intentos y los contadores; nunca se imputan métricas faltantes con cero. Las estimaciones usan mediciones completas compatibles, y reportan explícitamente cuántos registros tienen costo o memoria desconocidos.

La regresión `test_sigkill_resume_measurements_preserve_unknown_attempt_costs` mata realmente un proceso sintético con SIGKILL después del checkpoint 16, reanuda en otro proceso hasta 64, comprueba que no se duplican transiciones y ejecuta mediciones tanto con el formato nuevo como con un intento antiguo sin campos finales.

Estado agregado: pendiente, parcial, fallido, pendiente de evaluación o completo. No declara completa una comparación sin el calendario requerido. Un fallo evaluativo queda visible y conserva progreso para reintento. Códigos CLI: 0 completo/preparación; 3 parcial o reporte pendiente; fallo de código termina con error.

`validate_pong_online_recovery` publica checkpoints, envía USR1 real desde otro proceso, reanuda en proceso distinto, compara con continuo, intenta segundo writer, repite evaluación y reconstruye reporte. Por default usa entorno simulado. `--atari` exige Linux y usa A3; comandos preparados en la guía. No se envían jobs ni se abre test reservado al generar esta entrega.
