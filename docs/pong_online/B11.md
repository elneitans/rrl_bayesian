# B11 — costo, caché y almacenamiento

Fases: emulación/extracción, relaciones/codificación, predicción, política/collector/TD, selección/targets, ajuste, checkpoint/logs. Evaluación se contabiliza aparte por episodio. La instrumentación resta componentes medidos para evitar doble contabilización. Se conservan RSS máximo del proceso, bytes de logs/checkpoints y recursos/duración por intento.

Caché LRU por agente batch: versión e identidad del modelo, catálogo, valores y máscara. Guarda el resultado del camino de referencia, sin cambiar sumas, draws, árboles ni desempates. No consume RNG. Se invalida al publicar Q y al cambiar objeto de modelo. Cuenta bytes con margen conservador para objetos Python y tiene límite configurable (1 MiB default). No persiste caché ni la aplica al baseline incremental.

`logs/*.jsonl` son segmentos inmutables con hash y enlace al anterior. El checkpoint incluye solo el último enlace; el collector conserva filas pendientes hasta publicar. `status.json` confirma de forma atómica una frontera de modelo/contador/logs. Un archivo posterior no confirmado no participa de recuperación. El reporte reconstruye filas por streaming, usando memoria de un segmento más referencias. Replay es FIFO acotado; solo se retiene el último registro de fit en memoria. No se reescribe todo el historial en cada checkpoint.

Inventario obligatorio antes de limpiar. Retención protege checkpoints de calendario (evaluados o pendientes), final/último y respaldo anterior, además de identidades evaluativas existentes. `cleanup` es explícito y exclusivo para v2; retira blobs no protegidos y logs no confirmados, conserva metadatos de cadenas y todos los logs confirmados. No modifica datos históricos.

Pruebas: predicciones/acciones/RNG/learning exactos con/sin caché, invalidación, límite de memoria, fallo de publicación, reconstrucción sin duplicados y benchmark con mismo modelo/lote. El reporte de recuperación incorpora el microbenchmark antes/después. No se exige una aceleración mínima; tasas de entornos simulados no estiman Atari. Los tamaños de checkpoint crecen hasta llenar replay/modelos; la incertidumbre se explicita en dry-run.
