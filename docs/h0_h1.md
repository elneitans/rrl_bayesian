# Implementación H0 y H1

Fecha: 2026-09-17. Base histórica: `cf58dc7`.

Nota de avance: después de esta entrega se implementó [H2](h2.md).
Este informe conserva el alcance y la validación originales de H0/H1.

## Alcance entregado

H0 establece un baseline incremental verificable y H1 proporciona la representación
y el árbol binario independiente. No se ha implementado BART, MCMC ni fitted Q;
esa inferencia comienza en H2. El control frecuentista binario para la campaña
experimental también queda pendiente: el baseline corregido sigue usando `Node`
y la representación histórica para aislar la corrección TD.

El código original `relational_regresion_tree.py`, `preprocessing.py`,
`utilities.py` y `train_and_test.py` se conserva sin cambios. La variante
`rrtl_legacy` se identifica con esos archivos y el commit de origen.

## H0: baseline corregido

`bayesian_rrtl/baseline.py` implementa `CorrectedRRLAgent`, reutilizando el
F-test, las estadísticas, las acciones y el preprocesamiento originales.
La nueva ejecución usa `train_baseline.py` y configuraciones JSON.

Cambios respecto de legacy:

| Aspecto | Comportamiento corregido |
|---|---|
| Actualización TD | `Q(s,a) += eta_q * (r + gamma * b * max Q(s',a') - Q(s,a))`, con la acción realmente ejecutada, también después del remuestreo de acciones |
| Terminal real | `b=0`, sin consultar predicciones del estado siguiente |
| Truncación | `b=1` por defecto; configurable. Se usa la observación final de un entorno sin autoreset |
| Presupuesto agotado | No se convierte en terminal; se registra y aprende la última transición antes de detenerse |
| Recompensas | Se registran recompensa original, transformada y ambos retornos acumulados |
| Selección de modelo | Se guarda y evalúa siempre el checkpoint final; no se selecciona por récord de entrenamiento |
| Aleatoriedad | RNG separados para exploración y semillas del entorno; la evaluación trabaja sobre una copia privada |
| Semillas | Listas disjuntas de entrenamiento/configuración, validación y test; las semillas generadas por episodio excluyen las reservadas |
| Acciones repetidas | Misma opción aplicada a entrenamiento y evaluación de Breakout; legacy se conserva tal cual |
| Reinicio FIRE | Acepta `seed` y `options`; devuelve la observación del nuevo reset si termina durante la inicialización |
| Resultados | Cada ejecución contiene configuración resuelta, hash, versiones, hashes de fuentes, registros y resumen |

La recompensa transformada sigue siendo `sign(r)` en Breakout/DemonAttack y
`sign(r)+0.1` en Pong. La evaluación usa recompensa original. El límite temporal
se aplica dentro de FIRE: las dos acciones de inicio cuentan para el límite
del entorno, pero no para `n_iterations` ni para los retornos del agente,
siguiendo la exclusión histórica de las acciones de inicio.

El checkpoint v1 contiene árboles, configuración, contadores, epsilon, estados
RNG, semillas y buffer de acciones. Permite cargar y evaluar el modelo. **No
permite reanudación exacta a mitad de episodio**: no guarda el emulador ni el
historial visual. El runner rechaza reiniciar entrenamiento sobre una instancia
ya entrenada. La reanudación se implementará y verificará en H5.

`datasets/make_train_dataset_per_game.py` ahora admite el mismo archivo de
configuración y reconoce logs históricos y corregidos. Conserva la variante
en la tabla; no mezcla ambos experimentos silenciosamente.

## H1: representación y árboles

El núcleo importa solamente NumPy y la biblioteca estándar:

- `encoding.py`: `RelationKey`, `RelationalEncoder` y `EncodedBatch`.
- `rules.py`: `Rule` y `RuleCatalog`, con probabilidades por relación y por regla.
- `tree.py`: árbol binario inmutable, predicción, particiones y validación de soporte.

Las claves incluyen `type`, `name`, `obj1`, `obj2` y `obj3`. Los tiempos se
conservan en los nombres de objetos. El catálogo se ordena por significado,
tiene versión y SHA-256, y se puede serializar a JSON. El encoder acepta los
`Fact` actuales sin importar `preprocessing.py`. Rechaza valores contradictorios,
categorías inválidas y relaciones no incluidas en el catálogo. `from_states`
permite inferir el catálogo una sola vez sobre un dataset fijo; para datos nuevos
se debe proporcionar un catálogo completo explícito o crear una nueva versión.

Los códigos categóricos no son distancias: comparativas `less/same/more` y
lógicas `False/True`. Los faltantes usan código `-1` y máscara `observed=False`.
Las reglas ordinarias envían faltantes a la rama falsa, y `is_missing` los
separa explícitamente. La ausencia de un hecho no se transforma en falsedad.

Todo estado, incluido el vacío, alcanza exactamente una hoja. Las hojas
almacenan una contribución `mu`; no hay retorno del Q de un nodo interno.
Las propuestas futuras podrán construir candidatos sin mutar el árbol original.

La elegibilidad recibe las filas que alcanzan el nodo bajo sus ancestros.
Una regla debe dejar al menos `min_child` observaciones por hijo y respetar
`max_depth`. Se agrupan reglas por relación: primero se elige la relación
uniformemente y luego una de sus reglas elegibles. Reglas diferentes que
producen la misma partición conservan identidades distintas; el kernel H2
deberá usar esta misma definición de espacio de árboles.

El preprocesamiento histórico puede descartar estados o producir hechos falsos
en ausencia de ciertos objetos. El encoder conserva lo que recibe: no recupera
información descartada ni reinterpreta esos hechos. Cambiar
`include_incomplete_states` o la semántica del extractor sigue siendo una ablación.

## Reproducir

Entorno verificado: Python 3.11.7, macOS ARM64, Gymnasium 1.1.1, ALE 0.10.2.
Las dependencias directas están en `requirements.txt`; la resolución completa
está en `requirements-lock.txt`. Graphviz también requiere el ejecutable
del sistema `dot`; solo es obligatorio para la exportación PDF y sus pruebas.

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python -m pip check
dot -V
.venv/bin/python -m pytest -q
```

Para probar H1 sin Atari, instalar `requirements-core.txt` en un entorno vacío
y ejecutar `.venv/bin/python -m pytest tests/test_encoding_tree.py -q`.
Para las pruebas de baseline sin ROMs: `-m 'not atari'`, con las dependencias
Python completas instaladas. Las pruebas Atari no se omiten silenciosamente
cuando faltan dependencias.

```bash
.venv/bin/python train_baseline.py --config configs/breakout_smoke.json
.venv/bin/python train_baseline.py --config configs/breakout_smoke.json --run 2
.venv/bin/python datasets/make_train_dataset_per_game.py \
  --config configs/breakout_smoke.json --output-dir results/smoke/aggregated
```

`--run` cambia el identificador, no la semilla; cambiar `seed` en la configuración
para réplicas independientes. Un directorio existente se rechaza para conservar
resultados. `--results-dir` permite usar otra raíz, y `--eval-split none` omite
evaluación. La opción por defecto es `validation`; `test` se ejecuta solo al
solicitarlo explícitamente. La regla de selección es siempre el modelo final.

Las configuraciones `breakout_baseline.json`, `pong_baseline.json` y
`demonattack_baseline.json` contienen todos los parámetros y presupuestos
históricos. No se han ejecutado esas campañas largas. El smoke test usa límites
temporales muy cortos para verificar el flujo; sus retornos no miden rendimiento.

La instalación actual de ALE incluye ROMs; se verificaron los tres juegos.
Referencias de compatibilidad:
[ALE 0.10](https://ale.farama.org/release_notes/) y
[terminación/truncación de Gymnasium](https://gymnasium.farama.org/api/env/).

## Validación

- Targets de una transición con acción no greedy y valores distintos en `s` y `s'`.
- Terminal, truncación con/sin bootstrap y rechazo de truncación sin observación final.
- Última transición, retorno, epsilon y checkpoint con episodio completo e incompleto.
- Repetición exacta del registro con la misma semilla en un entorno controlado.
- Evaluación repetible que no cambia árboles, estadísticas, RNG ni buffer de entrenamiento.
- Reinicio FIRE que devuelve la observación vigente.
- Catálogo independiente del orden, conflictos de hechos y persistencia del encoder.
- Ruteo total, faltantes, límites de profundidad y elegibilidad bajo ancestros.
- Atari real para tres juegos y dos representaciones; compatibilidad de sus `Fact` con H1.
- Entrenamiento legacy corto y caracterización de su omisión de la última fila.
- Runner desde otra carpeta, manifiesto, checkpoint, Graphviz y test reservado.

Los resultados concretos de la ejecución se guardan en
`docs/validation_h0_h1.json`. El siguiente entregable es H2: marginal gaussiana,
priors y sampler grow/prune con posterior exacta de referencia.

## Correcciones posteriores de H0

El baseline corregido excluye del F-test los candidatos cuya varianza total
es cero. Conserva sus estadísticas y refinamientos para poder reconsiderarlos
cuando aparezcan targets distintos; también protege las hojas creadas por splits.
Los archivos legacy permanecen intactos.

La CLI admite evaluación independiente de un checkpoint local confiable:

```bash
.venv/bin/python train_baseline.py \
  --checkpoint results/smoke/rrtl_corrected/Breakout/comparative_version/run_1/final_checkpoint.pkl \
  --eval-split test
```

Se debe sustituir la ruta por la del checkpoint existente. El runner recupera
su configuración guardada, verifica su hash y evalúa las semillas del split
solicitado. Escribe `test.json` o `validation.json` junto al checkpoint,
reemplazando el resultado anterior del mismo split. No entrena ni modifica el
checkpoint, el manifiesto o el registro de entrenamiento. `--checkpoint` no
admite `--config`, `--run`, `--results-dir` ni `--eval-split none`.

Validación de estas correcciones: suite completa **77 passed**, sin fallos ni
omisiones (incluye Atari real y evaluación CLI del checkpoint existente).
Informe: `results/h0_revision_tests.xml`. Ruff pasa en los cuatro archivos Python
modificados para esta revisión; los cuatro archivos legacy coinciden con `cf58dc7`.
Las 13 advertencias son deprecaciones de Pyparsing emitidas por Matplotlib.
