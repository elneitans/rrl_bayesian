# H3: ensemble BART y Bayesian backfitting

Implementado el 2026-09-17. El regresor aprende una suma de `m` árboles sobre un
batch relacional fijo. La integración con Q-learning sigue siendo H5; este
hito no cambia el entrenamiento Atari ni implementa General BART (H4).

## Implementación

- `bayesian_rrtl/ensemble.py`: `BARTRegressor`, `PredictionCache`, snapshots
  inmutables `EnsembleDraw` y resultado `BARTPosterior`.
- `bayesian_rrtl/sampler.py`: actualización compartida `update_tree`, usada
  tanto por H2 como por H3. Mantiene la aceptación MH marginal y el muestreo de
  hojas después de propuestas aceptadas, rechazadas o imposibles.
- `bayesian_rrtl/diagnostics.py`: diagnósticos de varias cadenas sobre funciones
  identificables del ensemble.
- `bayesian_rrtl/exact.py`: referencia adicional que integra conjuntamente todas
  las hojas de cada ensemble pequeño mediante una normal multivariante.
- `experiments/validate_h3.py`: cuatro problemas sintéticos con datos congelados,
  cuatro cadenas independientes por problema y resultados exportables.

Cada árbol tiene varianza de hoja `tau² = (0.5 / (k * sqrt(m)))²`. Al inicio,
la media normalizada de las respuestas se reparte entre las `m` raíces.
Un barrido recorre los árboles en orden y para el árbol `j` calcula:

```text
otros = predicción_total - predicción_j
residuos_j = y_normalizada - otros
árbol_j = MH de estructura + muestreo de todas sus hojas
predicción_j = árbol_j.predict(X)
predicción_total = otros + predicción_j
```

Así, cada actualización utiliza las versiones más recientes de los demás
árboles. La varianza residual compartida se muestrea **una vez por barrido**, con
los residuos del ensemble completo. No se actualiza ruido entre árboles.

Cada draw retenido contiene los `m` árboles completos y su `sigma2`, sin
referencias al caché mutable de trabajo. Los árboles son inmutables. El
regresor reinicia una cadena en cada `fit`, copia los datos y no cambia
minibatches, objetivos, catálogo, escala ni priors dentro de la cadena.

Las predicciones **suman árboles dentro de cada draw** y después promedian
los draws. El centro `c` y ancho `W` se aplican una sola vez a la suma:
`prediction = c + W * sum(tree_predictions)`. El predictor observacional
además incorpora ruido gaussiano de varianza `sigma2 * W²`.

## API y uso

El entorno existente de H0–H2 ya contiene las dependencias. Para un entorno
mínimo basta `requirements-bayesian.txt`; no se necesitan Atari, OpenCV,
Graphviz ni ArviZ para usar este regresor o sus diagnósticos.

Durante esta validación, la carga de una extensión de NumPy desde `.venv`
quedó bloqueada por el sistema de archivos local. El experimento ampliado usa
el Python local con las mismas versiones NumPy 1.26.4 y SciPy 1.12.0. Para
reproducir con dependencias completas se puede crear un entorno fuera de la
carpeta sincronizada e instalar el mismo `requirements-lock.txt`; no se
cambiaron las dependencias del proyecto para resolver el bloqueo.

```python
import numpy as np
from bayesian_rrtl.ensemble import BARTRegressor
from bayesian_rrtl.priors import FixedScale, TreePrior, calibrate_noise

# x: EncodedBatch de H1; y: vector en las unidades originales.
# y_pilot: respuestas de un piloto de entrenamiento reservado para calibración.
scale = FixedScale(-0.5, 0.5)
calibration = calibrate_noise(scale.normalize(y_pilot))
regressor = BARTRegressor(
    m=20, k=2,
    tree_prior=TreePrior(max_depth=6, min_child=1),
    noise_prior=calibration.prior,
    scale=scale,
)
posterior = regressor.fit(x, y, np.random.default_rng(42), burn_in=500, draws=1000)
mean = posterior.predict_mean(x)                         # [n_states]
latent = posterior.predict_latent_draws(x)               # [draws, n_states]
observed = posterior.predict_observation_draws(x, np.random.default_rng(43))
print(posterior.diagnostics())
```

`m=20` es el valor inicial de desarrollo, no un ajuste validado para Atari.
`fixed_sigma2` permite pruebas con una varianza normalizada conocida; por defecto
se muestrea el ruido. `verify_cache=True` recompone todas las predicciones
**después de cada árbol**, útil para auditar residuos y cachés en pruebas pequeñas.
Este control tiene costo adicional y está desactivado por defecto.

El resultado conserva los priors, escala, `k`, catálogo/dataset identificados
por hash, burn-in, muestras completas, traza, tiempo de ajuste y objetivos fuera
de escala. Se conservan todos los sweeps posteriores al burn-in, sin thinning.
La persistencia versionada del agente y su reanudación siguen en H5.

## Diagnósticos de cadenas

```python
from bayesian_rrtl.diagnostics import posterior_diagnostics

chains = [regressor.fit(x, y, np.random.default_rng(seed), burn_in=1000, draws=2000)
          for seed in [10, 11, 12, 13]]
report = posterior_diagnostics(chains, x_reference)
```

Se comparan predicciones latentes en estados de referencia, varianza residual,
número total de hojas y profundidad máxima. No se comparan índices de árboles
intercambiables. Las cadenas deben corresponder a los mismos datos, priors,
escala y número de árboles/muestras; mezclas incompatibles se rechazan.

Se calcula R-hat rank-normalized, dividido y plegado, junto a ESS bulk y tail.
El estimador usa autocovarianzas FFT y secuencias iniciales positivas/monótonas.
Se limita ESS al número de draws de forma conservadora. Referencias:
[Stan, posterior analysis](https://mc-stan.org/docs/reference-manual/analysis.html) y
[Vehtari et al.](https://arxiv.org/abs/1903.08008).

Los resultados se contrastaron con ArviZ 0.21.0 en una instalación temporal
separada: [referencia numérica](diagnostics_reference_h3.json). R-hat coincide
hasta precisión numérica; ESS coincide o difiere menos de 1% después de aplicar
el tope, por el tratamiento de los últimos retardos. Las pruebas incorporan
esos resultados independientes y no requieren ArviZ instalado.

`status="ok"` indica que el diagnóstico se pudo calcular, **no que la cadena
convergió**. `constant` devuelve R-hat y ESS no disponibles; `stuck` identifica
cadenas constantes en valores distintos. Con número impar de draws se descarta
el draw central de cada cadena al dividirla. La guía del experimento es
R-hat <= 1.01 y ESS bulk >= 400; los indicadores no garantizan convergencia global.

## Validación y reproducción

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m experiments.validate_h3 --output results/h3_validation
.venv/bin/python -m experiments.validate_h3 \
  --output results/h3_validation_extended --burn-in 2000 --draws 10000
```

Los directorios deben ser nuevos. Cada problema exporta el encoder, datos,
draws de predicción/ruido/complejidad y diagnósticos; el resumen incluye
configuración, semillas, versiones y hashes de fuentes. Las salidas del piloto
se conservan aunque indiquen mezcla insuficiente; no se sobrescriben al ampliar
el presupuesto. Las semillas de cadenas son distintas; todos los ajustes de un
problema usan exactamente el mismo dataset.

Pruebas nuevas:

1. `m=1` reproduce H2 muestra por muestra, tanto con ruido fijo como desconocido.
2. Actualizaciones secuenciales usan residuos recientes y muestrean ruido una vez.
3. Cachés coinciden con recomputación completa después de cada árbol.
4. Suma de árboles, promedio entre draws, centro/escala y ruido predictivo correctos.
5. Muestras y datasets previos no cambian al ejecutar otro ajuste.
6. Ensemble de dos árboles contrastado con integración gaussiana conjunta: medias,
   varianzas y frecuencias estructurales. La referencia no multiplica marginales
   individuales de árboles, pues eso ignoraría la dependencia inducida por la suma.
7. El prior de la suma de raíces conserva su varianza al cambiar `m`.
8. Configuración por defecto de 20 árboles con auditoría de caché.
9. Diagnósticos sobre cadenas iid, AR(1), desplazamientos, cambios de escala,
   tendencias, empates y cadenas degeneradas, más comparación independiente con ArviZ.

Los cuatro sintéticos son señal nula, función por tramos, interacción y evento
raro. Este último tiene 8 observaciones del estado infrecuente entre 128. Se
mide recuperación de señal y mezcla en cuatro estados conocidos; no se presenta
como garantía sobre eventos no observados ni como estudio repetido de cobertura.

Los resultados medidos se registran en [validation_h3.json](validation_h3.json).
El siguiente hito secuencial es H4 (General BART y movimientos adicionales); la
integración por bloques con RL corresponde a H5.

## Resultados de esta entrega

La suite completa terminó con **65 pruebas aprobadas**, sin fallos ni omisiones.

En cada sintético se ejecutaron cuatro cadenas de cinco árboles, con 2000
sweeps de burn-in y 10000 muestras retenidas por cadena.

| Sintético | RMSE de la señal | R-hat máximo de predicciones | ESS bulk mínimo de predicciones |
|---|---:|---:|---:|
| null | 0.00440 | 1.00133 | 5094 |
| piecewise | 0.01191 | 1.00037 | 9961 |
| interaction | 0.01858 | 1.00003 | 39728 |
| rare | 0.01124 | 1.01248 | 282 |

Se conservan los diagnósticos que no cumplen la guía, sin declararlos convergidos:

- `interaction/total_leaves`: R-hat=1.01367, ESS bulk=435.6.
- `interaction/max_depth`: constant; R-hat y ESS no disponibles.
- `rare/prediction_0`: R-hat=1.01248, ESS bulk=282.2.
- `rare/max_depth`: constant; R-hat y ESS no disponibles.

La ejecución ampliada inicial terminó tras tres casos. El caso `rare` se
completó por separado con los mismos parámetros en
`results/h3_validation_rare_extended/`. El reporte reúne ambos resultados.
